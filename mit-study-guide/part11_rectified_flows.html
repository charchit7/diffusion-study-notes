Part 11Rectified Flows

Prerequisites You need Part 10 (Flow Matching) firmly in hand: the conditional flow-matching loss \(\mathcal{L} = \mathbb{E}\bigl\|\,u_t^\theta(x) - u_t(x\mid z)\bigr\|^2\), the linear interpolation \(x_t = (1-t)x_0 + t z\) with constant conditional velocity \(u = z - x_0\), and Euler sampling along a probability-flow ODE. You do not need to know anything about rectified flows yet.

11.1 The Curved-Trajectory Problem

Intuition

After Part 10 you know how to train a velocity field \(v_\theta(x,t)\) and then generate a sample by solving the ODE

\[\frac{dx}{dt} = v_\theta(x, t), \quad x_0 \sim p_{\text{init}}.\]

To solve this ODE numerically you use Euler steps:

\[x_{t+h} \approx x_t + h\,v_\theta(x_t, t).\]

A single Euler step is exact only when the trajectory is a straight line (constant velocity, no curvature). If the trajectory curves, the Euler step veers off it and you accumulate error — so you need many small steps.

Curved path (many steps needed):

  noise x_0                          data x_1
     *                                   *
      \  ← true curved trajectory
       ~--.
           `--.
               `--~
                   \
                    *  (actual data)

Straight path (one step suffices):

  noise x_0 ——————————————————————— data x_1
     *   →   →   →   →   →   →   →   *

The central dream of rectified flows is to make the learned velocity field correspond to straight-line trajectories, enabling fast (ideally one-step) generation.

Why does standard flow matching give curved trajectories? Recall that flow matching with the linear interpolation trains the marginal velocity \(v_\theta(x, t)\) to match the average of all conditional velocities \(u = z - x_0\) that pass through the point \(x\) at time \(t\). If two different straight-line segments — say one from \((x_0^a, z^a)\) and another from \((x_0^b, z^b)\) — both pass through the same \(x\) at time \(t\), the marginal field learns their average direction. Following that averaged field curves away from either original line. Individual conditional paths are straight; the learned marginal field is not.

11.2 The Rectified-Flow Objective

Rectified flow (Liu et al., 2022, "Flow Straight and Fast") is flow matching with the linear interpolation path — which you already know from Part 10 — but with one crucial reframing: instead of conditioning on a single data point \(z\), we explicitly talk about pairs \((x_0, x_1)\) drawn jointly from some coupling \(\pi(x_0, x_1)\).

Formal Object

Let \(p_{\text{init}}\) be the initial distribution (e.g. \(\mathcal{N}(0,I)\)) and \(p_{\text{data}}\) be the data distribution. A coupling \(\pi(x_0, x_1)\) is any joint distribution with marginals \(\pi(\cdot, x_1) = p_{\text{init}}\) and \(\pi(x_0, \cdot) = p_{\text{data}}\).

Given a coupling, define the linear interpolation at time \(t \in [0,1]\):

\[x_t = (1-t)\,x_0 + t\,x_1.\]

The conditional velocity along this straight line is constant:

\[u(x_t \mid x_0, x_1) = x_1 - x_0.\]

The rectified-flow loss trains a velocity network \(v_\theta : \mathbb{R}^d \times [0,1] \to \mathbb{R}^d\) by:

\[\mathcal{L}_{\text{RF}}(\theta) = \mathbb{E}_{t \sim \mathcal{U}[0,1],\,(x_0, x_1) \sim \pi} \bigl\|\,v_\theta(x_t, t) - (x_1 - x_0)\bigr\|^2.\]

Equation breakdown — every symbol

SymbolShape / TypeMeaning
\(v_\theta(x_t,t)\)\(\mathbb{R}^d\)Neural network predicting velocity at position \(x_t\), time \(t\)
\(x_0\)\(\mathbb{R}^d\)Noise sample drawn from \(p_{\text{init}}\)
\(x_1\)\(\mathbb{R}^d\)Data sample drawn from \(p_{\text{data}}\)
\(x_t = (1-t)x_0 + t x_1\)\(\mathbb{R}^d\)Linearly interpolated point at time \(t\)
\(x_1 - x_0\)\(\mathbb{R}^d\)Target velocity: the constant direction from noise to data along the straight line
\(\pi(x_0, x_1)\)joint distributionThe coupling — determines which noise is paired with which data
\(t \sim \mathcal{U}[0,1]\)scalarUniformly sampled time step
\(\|\cdot\|^2\)scalarSquared Euclidean norm

Compare to the Part 10 loss \(\mathbb{E}\|u_t^\theta(x) - u_t(x\mid z)\|^2\): it is identical with \(z \leftrightarrow x_1\) and the conditional velocity being \(x_1 - x_0\). Rectified flow is a specific instance of conditional flow matching.

Subtle Point — Straight Lines vs Straight Field

Each individual trajectory \(t \mapsto (1-t)x_0 + t x_1\) is a straight line with constant velocity \(x_1 - x_0\). But the marginal velocity field \(v_\theta(x,t)\) that the network learns is not straight in general.

Why? At any given point \((x,t)\), many different pairs \((x_0^a, x_1^a)\) and \((x_0^b, x_1^b)\) can satisfy \(x_t = x\). Their straight-line directions \(x_1^a - x_0^a\) and \(x_1^b - x_0^b\) may differ. The network, minimising mean squared error, learns their conditional average:

\[v_\theta(x, t) \approx \mathbb{E}[\,x_1 - x_0 \mid x_t = x\,].\]

Following this averaged direction will in general curve away from any single line. This is the crossing problem explained next.

11.3 The Crossing Problem

Intuition — Averaging Arrows at Intersections

Imagine many rubber bands stretched across a room: each band goes from a noise point \(x_0^i\) straight to a data point \(x_1^i\). If two bands cross at the same point in the middle of the room, what direction should the wall (the network) push a particle sitting at that crossing? It cannot go both ways, so it averages. The average direction leads away from both target data points.

Visually:

  x_0^a ——————→ x_1^a
               ×         ← crossing at this point
  x_0^b ——————→ x_1^b

  Learned velocity at ×: average of (x_1^a − x_0^a) and (x_1^b − x_0^b)
  → points neither to x_1^a nor to x_1^b exactly.

The more crossings in a coupling, the more the marginal field deviates from any straight line — and the more Euler steps you need to follow it accurately.

Why does the independent coupling \(\pi = p_{\text{init}} \otimes p_{\text{data}}\) maximise crossings? When \(x_0\) and \(x_1\) are drawn independently, the straight-line segments from noise to data crisscross all over the space. The learned marginal field therefore curves substantially. This is the regime you train in on the first pass.

11.4 Reflow — The Key Idea

The insight of Liu et al. is: if we could pair each noise point with the data point it actually flows to under the current model, the resulting coupling would have far fewer crossings. Fewer crossings → straighter marginal field → fewer Euler steps needed. This procedure is called reflow.

Why Reflow Reduces — But Does Not Eliminate — Crossings

A tempting argument goes: "the reflow map is deterministic, so two segments crossing, \[(1-t)x_0^a + t x_1^a = (1-t)x_0^b + t x_1^b,\] is a measure-zero event — hence crossing-free." This argument is wrong: in \(d \ge 2\), exact segment crossings are measure-zero even for the independent coupling, and in \(d = 1\) a deterministic map (e.g. \(x_1 = -x_0\)) produces massive crossings. Determinism by itself proves nothing.

The correct statement (Liu et al. 2022): what genuinely cannot cross are the ODE trajectories of the trained flow \(v^{(1)}\), by uniqueness of ODE solutions. Rectification therefore never increases — and typically strictly decreases — every convex transport cost of the coupling, and increases the straightness of the flow. But the straight interpolants of the new pairs \((x_0, x_1')\) can and do still cross; the marginal field only becomes perfectly straight in the limit of repeated rectification — which is exactly why the algorithm below iterates (step 4).

The Reflow Algorithm

Reflow — Step by Step
  1. Train \(v^{(1)}_\theta\) on the independent coupling \(\pi^{(1)} = p_{\text{init}} \otimes p_{\text{data}}\) using the rectified-flow loss. This is standard flow matching with linear paths.
  2. Generate paired data (build \(\pi^{(2)}\)). For each noise sample \(x_0 \sim p_{\text{init}}\), integrate the current model forward: \[x_1^{(1)} = x_0 + \int_0^1 v^{(1)}_\theta(x_t, t)\,dt \approx x_0 + \sum_{k} h\,v^{(1)}_\theta(x_{t_k}, t_k).\] Store the pair \((x_0, x_1^{(1)})\). Crucially this is a deterministic map: the same \(x_0\) always produces the same \(x_1^{(1)}\). The ODE trajectories that produced these pairs cannot cross one another, and the resulting coupling has lower transport cost — though the straight interpolants of the new pairs may still cross.
  3. Train \(v^{(2)}_\theta\) on the new coupling \(\pi^{(2)}\) (the stored pairs) with the same loss: \[\mathcal{L}^{(2)} = \mathbb{E}_{t,(x_0, x_1^{(1)}) \sim \pi^{(2)}} \bigl\|v_\theta(x_t, t) - (x_1^{(1)} - x_0)\bigr\|^2.\] Because \(\pi^{(2)}\) has far fewer crossings, the learned field \(v^{(2)}\) is straighter.
  4. Iterate. Apply step 2–3 again using \(v^{(2)}\) to produce \(\pi^{(3)}\), train \(v^{(3)}\), and so on. Each round further straightens the trajectories.
Intuition — Why Each Round Helps

After the first training, the model already pushes noise towards data roughly correctly but along a curved path. The reflow step says: "let me actually follow that curved path to find out where each noise particle ends up, and then pair them permanently." Now when I retrain, every pair has a dedicated straight-line corridor that doesn't compete with other pairs. The new model learns a field that is much closer to constant along each trajectory.

Think of it as untangling a bowl of spaghetti: the first cook (training) roughly sorts the strands; the reflow step picks up each strand and lays it straight; repeat until every strand is fully straight.

11.5 Distillation to One Step

After one or two reflow iterations the trajectories are nearly straight. If they were exactly straight, the velocity would be constant along each path and a single Euler step of size 1 would already be exact:

\[x_1 \approx x_0 + v_\theta(x_0,\, 0).\]

Because in practice they are only nearly straight, Liu et al. add an explicit distillation training phase: fit the (student) model on reflow pairs \((x_0, x_1')\) with the single-step objective \(\bigl\|x_1' - x_0 - v_\theta(x_0, 0)\bigr\|\) (or a perceptual loss), so that one Euler step reproduces the full integration. One-step sampling without this phase is only exact for exactly-straight trajectories. In practice, one or two rounds of reflow followed by distillation achieves generation quality competitive with many-step methods using a single network evaluation — the core claim of "Flow Straight and Fast".

11.6 Connections

Connection — Part 10 (Flow Matching)

Rectified flow is exactly the linear-interpolation instance of conditional flow matching from Part 10. The CFM loss with \(x_t = (1-t)x_0 + t z\) and \(u_t(x\mid z) = z - x_0\) is the rectified-flow loss with \(x_1 \equiv z\) and independent coupling. The only new ingredient is the reflow procedure that replaces the independent coupling with a deterministic one.

Connection — Part 9 (Probability Flow ODE)

In Part 9 you learned that the probability-flow ODE has a velocity field \(u_t(x) = f_t(x) - \frac{1}{2}g_t^2\,\nabla\log p_t(x)\). For general diffusion schedules, this field is highly non-linear in \(x\) and \(t\) — causing trajectory curvature. Rectified flow can be viewed as choosing the schedule and training procedure so that this field becomes as linear as possible, making the PF-ODE trivially solvable.

Connection — Part 12 (Stable Diffusion 3)

Stable Diffusion 3 uses exactly the rectified-flow / linear-path flow-matching formulation (Esser et al., 2024 "Scaling Rectified Flow Transformers for High-Resolution Image Synthesis"). The training loss is the same \(\mathcal{L}_{\text{RF}}\) above. The key architectural change is a transformer backbone (DiT-style) instead of a U-Net. Part 12 will examine how this scales to image generation; all the mathematics you learn here transfers directly.

11.7 PyTorch — Toy 2-D Example

We demonstrate three things in 2-D: (a) a single rectified-flow training step, (b) a reflow data-generation step, and (c) a sanity check that under a fixed coupling the target velocity is constant along the path (it should be — since it equals \(x_1 - x_0\) regardless of \(t\)).

# teaching code, not security-sensitive RNG
# Part 11 — Rectified Flows: 2-D toy demonstration
# Requires: torch (any modern version), no GPU needed.

import torch
import torch.nn as nn

torch.manual_seed(0)  # reproducibility

# ── Distributions ───────────────────────────────────────────────────────────
# p_init : isotropic Gaussian in R^2
# p_data : mixture of two Gaussians ("two moons" proxy)

def sample_noise(n):
    """Draw n samples from p_init = N(0, I_2).  Shape: (n, 2)."""
    return torch.randn(n, 2)

def sample_data(n):
    """Draw n samples from p_data (two-cluster mixture).  Shape: (n, 2)."""
    half = n // 2
    c1 = torch.randn(half,    2) * 0.3 + torch.tensor([ 2.0,  0.0])
    c2 = torch.randn(n - half, 2) * 0.3 + torch.tensor([-2.0,  0.0])
    return torch.cat([c1, c2], dim=0)

# ── Tiny velocity network ────────────────────────────────────────────────────
# Input : [x (2-D), t (scalar)] → concatenated to a 3-D vector
# Output: velocity v_theta(x, t) in R^2

class VelocityNet(nn.Module):
    def __init__(self, hidden=64):
        super().__init__()
        # x is 2-D, t is 1-D → input size 3
        self.net = nn.Sequential(
            nn.Linear(3, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
            nn.Linear(hidden, 2),   # output: 2-D velocity
        )
    def forward(self, x, t):
        # x: (batch, 2), t: (batch, 1)  →  concat → (batch, 3)
        xt = torch.cat([x, t], dim=-1)
        return self.net(xt)

model = VelocityNet()
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)

# ── (a) Rectified-flow training step ────────────────────────────────────────
# Loss = E_{t, (x0,x1)} || v_theta(x_t, t) - (x1 - x0) ||^2

def rf_train_step(model, optimizer, batch_size=256):
    model.train()
    optimizer.zero_grad()

    x0 = sample_noise(batch_size)        # (B, 2) — noise samples
    x1 = sample_data(batch_size)         # (B, 2) — data samples (independent)

    # Sample t uniformly in [0, 1] for each pair
    t  = torch.rand(batch_size, 1)       # (B, 1)

    # Linearly interpolate: x_t = (1-t)*x0 + t*x1
    xt = (1 - t) * x0 + t * x1          # (B, 2)

    # Target velocity: the constant direction from noise to data
    target = x1 - x0                     # (B, 2) — does NOT depend on t

    pred = model(xt, t)                  # (B, 2) — network prediction

    loss = ((pred - target) ** 2).mean()
    loss.backward()
    optimizer.step()
    return loss.item()

# Quick training loop (50 steps for illustration)
for step in range(50):
    loss_val = rf_train_step(model, optimizer)

print(f"Loss after 50 steps: {loss_val:.4f}")
# Expected output (approximate): Loss after 50 steps: 1.5xxx
# (high because we only trained 50 steps on a random tiny net)

# ── (b) Reflow: generate new deterministic couplings ────────────────────────
# For each x0, integrate v_theta forward with Euler steps to get x1'.
# (x0, x1') is the new coupling — deterministic, fewer crossings.

@torch.no_grad()
def reflow_generate_pairs(model, n=512, n_steps=50):
    """
    Integrate model from t=0 to t=1 (Euler, n_steps steps).
    Returns (x0, x1_prime): shape (n, 2) each.
    These rectified pairs (lower transport cost, fewer crossings)
    feed the next reflow round.
    """
    model.eval()
    x0 = sample_noise(n)                 # (n, 2) — fixed noise samples
    x  = x0.clone()
    h  = 1.0 / n_steps                   # Euler step size

    for k in range(n_steps):
        t_k = torch.full((n, 1), k * h)  # (n, 1) — current time
        v   = model(x, t_k)              # (n, 2) — velocity at (x, t_k)
        x   = x + h * v                  # Euler step

    x1_prime = x                         # (n, 2) — deterministic endpoint
    return x0, x1_prime

x0_pairs, x1_pairs = reflow_generate_pairs(model)
print(f"Reflow pairs shape: x0={x0_pairs.shape}, x1'={x1_pairs.shape}")
# Expected output: Reflow pairs shape: x0=torch.Size([512, 2]), x1'=torch.Size([512, 2])

# ── (c) Sanity check: constant velocity under a FIXED coupling ───────────────
# For a FIXED pair (x0, x1), the TARGET velocity x1 - x0 is the SAME at all t.
# Verify this analytically (no network needed — it is definitional).

x0_fixed = torch.tensor([[1.0, 0.5]])   # one fixed noise point
x1_fixed = torch.tensor([[3.0, 2.0]])   # one fixed data point
target_vel = x1_fixed - x0_fixed        # constant direction = [2.0, 1.5]

print("\nTarget velocity at different t values (should be IDENTICAL):")
for t_val in [0.0, 0.25, 0.5, 0.75, 1.0]:
    t_tensor = torch.tensor([[t_val]])
    # x_t changes with t, but the TARGET velocity does not
    xt = (1 - t_tensor) * x0_fixed + t_tensor * x1_fixed
    tv  = x1_fixed - x0_fixed          # always the same vector
    print(f"  t={t_val:.2f} | x_t={xt.squeeze().tolist()} | target_vel={tv.squeeze().tolist()}")

# Expected output:
#   t=0.00 | x_t=[1.0, 0.5]  | target_vel=[2.0, 1.5]
#   t=0.25 | x_t=[1.5, 0.875]| target_vel=[2.0, 1.5]
#   t=0.50 | x_t=[2.0, 1.25] | target_vel=[2.0, 1.5]
#   t=0.75 | x_t=[2.5, 1.625]| target_vel=[2.0, 1.5]
#   t=1.00 | x_t=[3.0, 2.0]  | target_vel=[2.0, 1.5]
#
# This confirms: the per-pair straight-line target is constant in t.
# The NETWORK output v_theta(x_t, t) won't be constant (it's averaging over
# many crossing pairs), but the TARGET is. Each reflow round reduces that
# crossing ambiguity, moving the average closer to the individual targets.

11.8 Summary and Checkpoint

Here is the full arc of Part 11 in one paragraph. Rectified flow is flow matching with linear interpolation but with a deliberate procedure — reflow — that replaces the naive independent coupling with a deterministic one obtained by following the current model. Each rectification round lowers the coupling's transport costs and reduces the crossing ambiguity, so the marginal velocity field moves closer to the individual target velocities and trajectories become straighter — perfectly straight only in the limit of repeated reflow — enabling one-step generation via a final distillation phase. Stable Diffusion 3 applies this idea at scale.
